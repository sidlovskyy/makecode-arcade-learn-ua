# КодКвест

«КодКвест» — безплатний україномовний курс Microsoft MakeCode Arcade для дітей 10–12 років. Він проводить учня через 24 покрокові місії у 6 рівнях: від першого спрайта й керування блоками до Python і власної завершеної гри.

Це статичний React-застосунок без бекенду, реєстрації, реклами й аналітики. Усі 145 практичних кроків мають локальний візуал: 88 схем блоків, 5 порівнянь «Блоки / Python», 13 текстових прикладів Python, 18 знімків редактора й 21 покрокову guide-картку. У кожній місії є самостійне випробування та мінітест. MakeCode відкривається окремо на офіційному сайті Microsoft.

## Локальний запуск

Потрібен сучасний Node.js із npm. Виконуйте команди з цієї директорії:

```bash
npm ci
npm run dev
```

Vite покаже локальну адресу сайту. `npm ci` встановлює відтворювані версії з `package-lock.json`.

## Перевірка і збірка

```bash
npm run visuals:setup # один раз: установлення Chromium на машині автора / CI
npm run check         # TypeScript + Vitest + тести інструментів + offline-аудит assets + збірка
npm run test:e2e      # Chromium: 1440×900, 820×1180, 390×844 + lightbox на 320×568
npm run visuals:test:online # окремо, з мережею: canary поточного MakeCode Arcade
npm audit --audit-level=high
```

Готовий статичний сайт з’явиться у `dist/`. Цю папку генерує Vite — не редагуйте її вручну й не додавайте до Git.

Окремі команди: `npm test` запускає компонентні та інтеграційні тести Vitest, `npm run visuals:test` — локальні тести інструментів автора, `npm run typecheck` — перевірку типів, `npm run build` — production-збірку. `npm run visuals:test:online` окремо перевіряє відповідність переможного блока Python-команді й запуск рівно чотирьох ворогів у поточному компіляторі та симуляторі офіційного MakeCode Arcade; потрібні мережа й Chromium. Після оновлення Playwright може знадобитися повторне `visuals:setup`; на Linux також потрібні системні бібліотеки Chromium.

E2E сам запускає Vite на `http://127.0.0.1:4173` (порт має бути вільний), проходить усі кроки через навігатор і кнопку продовження та перевіряє порядок контенту, локальність запитів, розміри зображень і відсутність горизонтального прокручування сторінки. Окремі сценарії перевіряють клавіатурне збільшення, справжній clipboard, старі URL, підказки, відновлення прогресу, мінітест, одноразове XP і перегляд завершеної місії. Знімки кожного кроку зберігаються у `test-results/`, HTML-звіт — у `playwright-report/`; обидві папки виключені з Git. Це перевірки сайту, а не автоматичне проходження ігор у симуляторі MakeCode.

## Візуали для авторів

У репозиторії збережено 93 SVG офіційних блоків MakeCode та шість повторно використовуваних WebP-знімків редактора. Крок посилається на asset через `src/lesson-visuals/generated-assets.ts`; рожеве виділення й українська виноска задаються окремо в контенті. Python залишається справжнім текстом зі збереженням відступів під час копіювання. Великі схеми можна збільшити; довгі рядки Python прокручуються всередині панелі коду.

```bash
npm run visuals:setup    # одноразове завантаження Chromium; потрібна мережа
npm run visuals:render   # мережа: перегенерувати повну партію SVG офіційним MakeCode
npm run visuals:capture  # мережа: оновити шість базових WebP-знімків редактора
npm run visuals:registry # локально: відновити типізований реєстр assets
npm run visuals:check    # offline: перевірити assets, каталог, реєстр і наявність файлів у Git
```

`visuals:render` надсилає авторські фрагменти до [офіційного renderer MakeCode Arcade](https://arcade.makecode.com/blocks-embed). Інструменти спочатку готують повну партію в `.visuals-tmp/`; помилка не замінює справні assets частковою партією. Каталоги в `tools/visuals/catalog/` використовують внутрішній TypeScript для генерації блоків. Цей код не імпортується в застосунок: учень вивчає Blocks і Python, а TypeScript самого React-сайту та renderer є матеріалом розробника.

Після `visuals:capture` відкрийте всі шість WebP у вихідному розмірі й перевірте приватність: немає особистих імен, email, аватарів, назв недавніх особистих проєктів, банерів чи браузерної панелі. Переконайтеся, що потрібні елементи видно й виноска кожного кроку вказує на один потрібний елемент. Після зміни інтерфейсу звірте координати також із `src/curriculum/editor-callouts.test.ts`.

Нові assets потрібно додати до Git разом із каталогами, контентом і згенерованим реєстром, перш ніж запускати строгий `visuals:check`. Повторне використання знімків не потребує повторної генерації. `npm run check` включає лише offline-аудит і локальні тести: він не викликає `visuals:setup`, `visuals:render`, `visuals:capture` чи `visuals:test:online`. Локальні тести використовують `tools/visuals/*.test.mjs`; мережевий canary збережено окремо в `campaign-06.online.mjs`. Після встановлення залежностей і Chromium команда `check` не потребує мережі. На CI слід заздалегідь установити Chromium.

## Як влаштований курс

- `src/curriculum/` — типізований зміст шести рівнів і 24 місій.
- `src/components/` — навчальна мапа, урок, кроки, випробування, тести й нагороди.
- `src/progress/` — локальне збереження та відновлення прогресу.
- `src/styles/` — дизайн-система Pixel Neon і адаптивні стилі.
- `src/assets/` — ілюстрація курсу та локальні SVG/WebP уроків.
- `src/lesson-visuals/` — типи, валідація візуалів, Python tokenizer і реєстр assets.
- `tools/visuals/` — інструменти автора та каталоги; не входять до runtime.
- `e2e/` — браузерні перевірки всіх уроків.

Маршрути використовують hash: `#/` відкриває мапу, а `#/lesson/<slug>` — конкретну місію. Тому прямі посилання працюють і на простому статичному хостингу без серверної маршрутизації.

Старі `#/lesson/vid-blokiv-do-kodu` та `#/lesson/typescript-u-hri` відкривають канонічні уроки «Від блоків до Python» і «Python у грі». Старий URL залишається читабельним; нові посилання й запам’ятований маршрут використовують `vid-blokiv-do-python` та `python-u-hri`. Прогрес прив’язаний до незмінних `lesson-21` / `lesson-22` і ID кроків, тому не губиться через перейменування.

## Приватність прогресу

Прогрес зберігається лише в `localStorage` поточного браузера під ключем `kodkvest.progress.v1`. Сайт не створює облікових записів, не збирає персональних даних і не синхронізує прогрес між пристроями. Очищення даних браузера видалить прогрес. Якщо сховище заблоковане, уроки працюють у межах відкритої сесії та показують попередження.

Runtime завантажує зображення, CSS і JavaScript із того самого хостингу: немає iframe, runtime-renderer чи сторонніх автоматичних запитів. Для читання курсу можна локально обслуговувати `dist/` без доступу до MakeCode; автоматичного offline-кешування чи service worker немає. Видимі посилання на `https://arcade.makecode.com/` відкривають зовнішній редактор із власними мережевими запитами. Авторські генерація й capture також потребують доступу до мережі.

## Статичне розміщення

1. Переконайтеся, що SVG, WebP, каталоги й реєстр закомічені; виконайте `npm ci`, `npm run visuals:check` і `npm run build`.
2. Завантажте вміст `dist/` на GitHub Pages, Cloudflare Pages, Netlify або інший статичний хостинг.
3. Публікуйте `dist/index.html` разом із усією папкою `dist/assets/`.

У Vite задано `base: './'`, тому посилання на JavaScript, CSS і всі візуали у production-збірці відносні й працюють у вкладеному шляху. [GitHub Pages публікує статичні HTML, CSS і JavaScript](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Для збірки в GitHub Actions задайте робочу директорію `site`, команду `npm ci && npm run visuals:check && npm run build` і артефакт `site/dist`. Якщо перевіряєте повний `check` та E2E у CI, попередньо встановіть Chromium. Хостингу не потрібні Node.js, Python, бекенд або доступ до renderer; під час звичайної збірки візуали не регенеруються.

GitHub Gist може зберігати вихідні або зібрані файли, але сам не показує React-застосунок як звичайний сайт. Для робочої вебадреси використовуйте GitHub Pages чи інший статичний хостинг. Сторонні сервіси, що відображають Gist як сайт, додають окрему залежність і не є рекомендованим способом публікації дитячого навчального проєкту.

- [ ] У `dist/` є `index.html`, хешовані JS/CSS, 93 SVG, шість WebP редактора й WebP-ілюстрація; немає source map, секретів або серверного коду.
- [ ] На ширинах desktop, tablet і mobile немає горизонтального прокручування чи перекритих елементів.
- [ ] Новий учень починає з місії 1; після оновлення сторінки незавершений урок відновлюється.
- [ ] Видно всі 24 місії; пошук, фільтр і скидання фільтрів працюють.
- [ ] Неправильна й правильна відповіді мінітесту мають зрозумілий зворотний зв’язок; завершення місії додає XP один раз.
- [ ] Невідомий slug показує «Місії не знайдено» та посилання назад до мапи.
- [ ] Усі дії доступні лише з клавіатури, focus добре видно, а режим reduced motion не має зайвих анімацій.
- [ ] За заблокованого `localStorage` курс лишається доступним і не обіцяє збереження прогресу.
